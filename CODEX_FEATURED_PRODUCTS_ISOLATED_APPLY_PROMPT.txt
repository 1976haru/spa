3. STRICT SEMANTIC DIFF GUARD
======================================================================

This is critical.

Before allowing the mutation, compare:
A. current parsed remote index.json
B. featured-preview proposed parsed index.json

The only allowed semantic differences are:

1. sections[FEATURED_SECTION_ID]
   - create it if absent
   - or update only that exact ShopSource-managed section

2. order
   - insert FEATURED_SECTION_ID once in the intended location
   - or move that same managed section if required
   - no other order changes

Everything else MUST be identical:
- all other sections
- all other settings
- header/footer
- hero
- category sections
- merchant-created sections
- presets/groups
- any unknown keys

Implement a reusable validator:
validate_isolated_featured_diff(before, proposed, section_id)

Return:
{
  "safe": true/false,
  "unexpected_paths": [...],
  "allowed_changes": [...]
}

If unexpected_paths is non-empty:
BLOCK WRITE.

Do not rely only on hashes for this check.
