Why this task exists
Recent homepage-assignment work repeatedly passed hundreds of unit tests but still failed in the actual user click path:
- Featured products initially returned 0/4 because existing Shopify products were not represented in ShopSource.
- [상품 4개 보기] initially appeared to do nothing because it only re-rendered existing text.
- Product selection quality initially allowed a vehicle-specific replacement part.
- Homepage auto design then crashed with:
  'list' object has no attribute 'strip'
- Featured product preview then fell into MANUAL_ACTION_REQUIRED because theme snapshot/prerequisites were not ready.

This pattern means the main problem is no longer one isolated bug.
The problem is insufficient integration validation across the real beginner workflow.

Mission
Stabilize the ENTIRE homepage automation path before adding any new assignment feature.

The user should be able to perform the normal Cabin Tidy flow without needing to understand internal prerequisites:

4. TYPE-SAFE INPUT NORMALIZATION AT MODULE BOUNDARIES
======================================================================

Fix the known crash:
'list' object has no attribute 'strip'

Known source:
homepage_automation.py hero_image_prompt() assumes avoid_styles is a string.

Add a small reusable normalization helper for text-like profile values.

Requirements:
- None -> ""
- str -> strip
- list/tuple/set -> normalize/flatten and join
- dict -> stable readable representation, not Python repr noise
- number/bool -> string
- nested containers -> safe finite normalization
- malformed/unexpected values must not crash homepage planning

Audit ALL homepage-related code for unsafe assumptions such as:
- value.strip()
- ",".join(value)
- direct string concatenation
- casefold/lower on non-string
- list expected but string supplied
- dict expected but list supplied

Fix at boundaries, not via scattered try/except.

Do NOT mutate persisted Brand Profile merely to satisfy display/prompt code.
