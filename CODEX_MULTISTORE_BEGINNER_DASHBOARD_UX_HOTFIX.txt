Context from real Store 001 screenshot
The page is functionally correct, but real UI inspection exposed beginner-facing inconsistencies:

1. Top summary says "설정 필요 0"
   while the table clearly shows:
   - Store 001 current status "설정 필요"
   - Store 002 "연결 설정 필요"
   - Store 003 "연결 설정 필요"

This happens because the top KPI counts raw check_status == NEEDS_SETUP,
while initial local-only rows often have check_status NOT_CHECKED even though beginner presentation derives a setup-required state.

2. The selected-store content appears ABOVE the outlined card,
while the card itself is mostly empty except "선택한 스토어의 다음 할 일".
The code creates selected_card_title/status/next/primary_action before entering the ui.card() context and then merely references those variables inside the card. NiceGUI elements are not reparented by variable reference.

3. Search placeholder says "스토어 이름, 번호, 이메일로 검색"
but service filtering actually searches store_id, store_name, shop_domain.
This should say "도메인", not "이메일".

1. SUMMARY KPI SEMANTICS
======================================================================

Top KPI "설정 필요" must reflect what the beginner sees, not raw internal check_status only.

Preferred rule:
- use multistore_status_label(row) or a presentation helper to classify rows
- count as setup-needed when beginner-facing status is one of:
  "설정 필요"
  "연결 설정 필요"
  "Shopify CLI 설치 확인 필요"
  "현재 테마 확인 필요"
  "다시 확인 필요"
  "확인 실패"
- do NOT count "준비 완료"
- "아직 확인 전" should be handled carefully:
  if next_action is credential/connection/cli/check due missing prerequisites, count as setup-needed;
  if no prerequisite issue but simply not checked, optionally count separately or not; avoid misleading 0.

Simpler acceptable implementation:
derive from next_action/status_label consistently so screenshot with 3 stores yields a non-zero setup count matching visible rows.

Do not force remote checks on page load just to calculate KPI.

- 003 not connected
