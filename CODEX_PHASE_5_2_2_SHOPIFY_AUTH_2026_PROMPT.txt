Why this hotfix is required
- Current ShopSource UI only accepts a static "Admin API access token".
- Shopify changed custom-app creation/authentication in 2026.
- New Dev Dashboard custom apps do not expose a static token for the merchant to copy from Shopify Admin.
- For server-side integrations acting on stores in the same Shopify organization, Shopify's current documented flow is the client credentials grant:
  client_id + client_secret -> POST /admin/oauth/access_token -> expiring access token.
- Client-credentials access tokens expire after ~24 hours (expires_in 86399), so ShopSource must obtain/refresh them automatically rather than asking the user to paste a new token each day.
- Existing legacy admin-created custom apps must continue to work with their existing static Admin API token.

Primary goal
Support BOTH:
1. DEV_DASHBOARD_CLIENT_CREDENTIALS (recommended/current)
2. LEGACY_ADMIN_TOKEN (existing older custom apps)

No real write is performed by this implementation.

3. CLIENT CREDENTIALS TOKEN SERVICE
======================================================================

Implement a ShopifyAuthService / credential provider that can supply a valid Admin API access token to all existing Shopify services.

For DEV_DASHBOARD_CLIENT_CREDENTIALS:

POST:
https://{shop}.myshopify.com/admin/oauth/access_token

Content-Type:
application/x-www-form-urlencoded

Fields:
grant_type=client_credentials
client_id=...
client_secret=...

Expected response:
- access_token
- scope
- expires_in

Rules:
- expires_in is expected around 86399 but do not hardcode exact success requirement
- cache token in memory with expires_at
- refresh/request a new token before expiry with a safety window (e.g. 5 minutes)
- after app restart, request a new token rather than requiring user input again
- one token request should be reused across calls while valid
- 401/token-expiry response may trigger one safe refresh+retry
- never infinite retry

Handle documented error:
shop_not_permitted
-> beginner message explaining the Dev Dashboard app/store must support this grant / be in the required organization context
-> do not downgrade to fake success

LEGACY_ADMIN_TOKEN:
- use current stored token behavior unchanged
- do not force migration during this phase
