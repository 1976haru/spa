==================================================

Phase 2.6.2 이후 실제 UI 상태:

- 수집된 후보 5
- 상품 상세 1/5
- MASTER 1/5
- Store 분류 1/5
- 현재 Batch 상품 4
- Batch 상세 대기 4
- Batch 상태 RUNNING
- Batch 실패 0

사용자가 [미완료 상품 자동 처리]를 누르면:

"처리할 미완료 상품이 없습니다."

toast가 뜬다.

하지만 실제로는 현재 Batch에 DETAIL_PENDING 4개가 이미 존재한다.

즉:
"미완료 상품이 없음"이 아니라
"이미 Queue에 들어가 있지만 첫 상세 탭을 시작하지 못한 상태"다.

==================================================
1. 코드상 정확한 원인
==================================================

src/shopsource/ui/v2.py의 process_unfinished()은:

result = batch_service.process_existing_candidates(...)

이후:

if result.get("queued"):
    ...
    open_queued_item(result["run_id"])
elif result.get("existing_imported"):
    ...
else:
    ui.notify("처리할 미완료 상품이 없습니다.")

로 동작한다.

현재 실제 상태에서는:
- NEEDS_DETAIL 4개가 이미 current Batch item으로 존재
- queue_existing_candidates()가 새로 추가한 queued = 0
- 기존 DETAIL_COMPLETE 1개는 이미 MASTER_IMPORTED라 existing_imported = 0
- result.detail_pending = 4

따라서 실제 처리할 pending item이 4개인데도
else로 떨어져 "처리할 미완료 상품이 없습니다."라고 잘못 표시된다.

그리고 queued > 0일 때만 open_queued_item()을 호출하므로,
이미 Queue에 들어 있는 DETAIL_PENDING 4개는 첫 상세 탭이 시작되지 않는다.

이것이 이번 Hotfix의 핵심이다.

==================================================
2. 목표
==================================================

[미완료 상품 자동 처리]를 누르면:

A. 새 Queue item이 추가된 경우
B. 이미 Queue에 DETAIL_PENDING item이 있는 경우
C. stale DETAIL_OPENED item을 회수할 수 있는 경우

모두 첫/다음 상세 처리를 실제로 시작해야 한다.

현재 실전 상태:

Batch RUNNING
DETAIL_PENDING 4
queued = 0

에서도
첫 상품 상세 탭이 자동으로 열려야 한다.

==================================================
3. process_unfinished() 수정
==================================================

process_existing_candidates() 결과 이후:

queued 값만 보지 마라.

다음 기준으로 판단:

if result["detail_pending"] > 0:
    open_queued_item(result["run_id"])

그리고 사용자 메시지는 상태에 맞게 구분.

예:

queued > 0:
"미완료 N개를 Batch에 연결하고 자동 처리를 시작합니다."

queued == 0 and detail_pending > 0:
"이미 Queue에 있는 미완료 N개 처리를 계속합니다."

existing_imported > 0 and detail_pending == 0:
"상세 완료 N개를 MASTER에 반영했습니다."

detail_pending == 0 and existing_imported == 0:
정말 처리할 것이 없을 때만
"처리할 미완료 상품이 없습니다."

==================================================
4. Queue kickoff helper
==================================================

UI 내부에서 중복 로직을 줄이기 위해
가능하면 helper를 만든다.

예:

def kick_batch(run_id):
    run = batch_service.get(run_id)
    if run["status"] == "RUNNING" and run["detail_pending"] > 0:
        open_queued_item(run_id)

단:
이미 DETAIL_OPENED item이 있으면
BatchSourcingService.next_item()이 None을 반환하므로
중복 탭은 열리지 않는다.

DB state를 source of truth로 유지.

==================================================
5. 현재 RUNNING 상태에서 "계속" 버튼 UX
==================================================

현재 batch_action("RESUME")은 RUNNING 상태에서:
"Batch is not paused."
오류가 난다.

UI에서 RUNNING일 때:
[계속] 버튼을 disabled 처리하거나
클릭 시 RESUME 대신 kick_batch()를 수행.

권장:
- PAUSED / PAUSED_NEEDS_USER / PENDING → RESUME
- RUNNING + detail_pending > 0 → "다음 처리 시작" 역할
- DONE_WITH_ERRORS → 실패 재시도 버튼 사용
- DONE → disabled

버튼 label을 동적으로:
RUNNING이면 "다음 처리"
PAUSED면 "계속"
으로 바꿔도 된다.

==================================================
6. "고급 NEEDS_DETAIL 전체 QUEUE"도 일관성 수정
==================================================

queue_existing()은 현재 queue_existing_candidates() 후
open_queued_item()을 호출한다.

이 동작은 맞다.

다만 새로 queued=0이더라도 기존 detail_pending >0이면
"이미 Queue에 있는 상품 처리를 시작합니다."
라고 표시.

새 Batch 생성 금지.

==================================================
7. 자동 kickoff 상태 진단
==================================================

render_batch() 또는 render_capture_summary()에서:

RUNNING
detail_pending > 0
DETAIL_OPENED = 0

이면:

"대기 중인 상품이 있습니다. 자동 처리를 시작할 수 있습니다."

표시 가능.

가능하면 페이지 최초 로드 시 무조건 자동으로 탭을 열지는 말고,
사용자의 [미완료 상품 자동 처리] 클릭을 kickoff로 유지한다.

브라우저 popup 차단 방지를 위해 user gesture 기반 window.open을 유지.

==================================================
8. Browser popup 제한 고려
==================================================

NiceGUI ui.run_javascript(window.open(...))는
사용자 클릭 이벤트에서 호출될 때 성공 가능성이 높다.

따라서:
- timer/poll에서 새 탭 시작 금지
- 페이지 load에서 자동 새 탭 금지
- 사용자가 [미완료 상품 자동 처리] 또는 [다음 처리]를 클릭했을 때 첫 탭 open

그 이후 다음 상품은 Chrome extension background.js의 chrome.tabs.create()가 처리한다.

==================================================
11. stale opened item
==================================================

DETAIL_OPENED가 45초 이상 stale이면
기존 next_item() recovery 규칙 유지.

user click kickoff 시:
stale item 회수
→ 재시도 또는 FAILED
→ 다음 가능한 item 반환

새 로직이 기존 recovery를 깨뜨리면 안 된다.
