4. Category planner
==================================================

Create a deterministic local CategoryPlanner.

Inputs:
- Store Profile
- store category
- concept
- include keywords
- exclude keywords
- risk rules
- current MASTER product titles/brands/categories if available
- existing KeywordEngine recipes
- prior sourcing campaign keyword/yield statistics if available

No paid API required.
No LLM/API network call required.

For Cabin Tidy, expected examples may include:
- Trunk Storage
- Seat Organization
- Console Storage
- Cargo
- Cup Holder
- Visor / Documents
- Trash / Cleanup
- Travel Storage
- Small Accessories

Do not hardcode Cabin Tidy-only behavior.
Implement generic rules with domain-specific seed expansion as data/config.

If the planner cannot confidently split a store, fallback:
- 1 broad store category
- several subtopic keyword groups

Never fail because category count is unknown.

==================================================
5. Keyword pool
==================================================

Each category may own 50–100+ candidate keywords.

BUT:
The runtime must NOT automatically use all of them.

Default limits:
- max active keywords per category = 15
- allowed range 3–30
- max pages per keyword = 5
- stale pages = 2
- max unique candidates per keyword = 300

These are plan defaults, configurable in advanced settings.

Keyword sources:
- Store Profile recipes
- include keywords
- category name expansions
- KeywordEngine recommendations
- previous successful keywords
- safe local phrase templates

Deduplicate case-insensitively.

==================================================
6. Keyword scoring
==================================================

Score keywords using available local evidence.

Suggested components:
- semantic/store fit
- category fit
- historical candidate yield
- low duplicate rate
- price fit
- quality fit
- low risk rate
- freshness / not recently exhausted

No single component can force deletion.

Keep poor keywords as DISABLED/LOW_PRIORITY rather than deleting.

==================================================
7. Quota allocation
==================================================

User gives only:
total sourcing target

Example:
10,000

Planner automatically allocates category quotas.

Use category weight based on:
- category importance/store relevance
- historical yield
- estimated breadth
- optional current product deficit

Rules:
- quotas sum exactly to total target
- minimum quota for enabled category
- avoid assigning huge quota to low-yield category
- unused quota can be reallocated in Phase 3.1

No equal split unless evidence is absent.

==================================================
8. Detail target
==================================================

User default experience should not require entering two numbers.

Default:
candidate target = user total
detail target = candidate target

Advanced option:
detail ratio
e.g. 25%, 50%, 100%

Mission/assignment preset can keep 100%.

11. Current LIVE campaign UI cleanup
==================================================

Current issue:
After candidate target is reached and campaign status becomes DETAILING,
search worker may be missing and UI shows ERROR.

Fix semantics:

If unique_candidates >= candidate_target and status in:
CANDIDATE_TARGET_REACHED
DETAILING
READY_FOR_SPARK
DONE

then search stage should display:

검색 단계: COMPLETE
후보: 2,000 / 2,000

Do not show old search-worker-missing error as an active blocking error.

During DETAILING instead show:
상세 Worker status
current ASIN
last detail success
detail completed / target
failure count

Historical search error can remain in event log.

Do not disturb current campaign DB state.
