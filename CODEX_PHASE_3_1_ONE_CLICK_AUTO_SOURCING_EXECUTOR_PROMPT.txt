==================================================
0. Final user experience
==================================================

The user wants:

1. Select Store
2. Enter desired sourcing count
3. Click:

[자동 소싱 시작]

Then ShopSource does the rest:
- loads/creates plan
- chooses categories
- chooses best keywords
- allocates quota
- runs Amazon search worker
- rotates keyword automatically
- stops low-yield keyword
- moves to next category
- reallocates unused quota
- reaches store target
- detail enrichment
- MASTER import
- Store classification
- prepares Spark package
- user receives result

No category-by-category clicking.
No keyword-by-keyword clicking.

==================================================
3. Category scheduler
==================================================

For each enabled category:
- category quota
- progress
- active keywords ranked by score

Scheduler chooses:
1. category with largest remaining weighted deficit
2. best non-exhausted keyword
3. page progression

When category quota reached:
move to another category.

When keyword exhausted:
move to next keyword.

When category cannot reach quota:
reallocate remaining quota to categories with:
- high yield
- remaining capacity
- store relevance

All category quotas + reallocations must preserve total target.

==================================================
4. Keyword stop conditions
==================================================

Stop current keyword when any:
- max pages reached
- max unique candidates reached
- stale 2 pages
- no DOM next link
- CAPTCHA pauses entire campaign
- campaign target reached

Do not keep traversing low-yield keyword indefinitely.

==================================================
5. Learning
==================================================

After each page:
update keyword runtime metrics:
- new candidates
- duplicates
- yield/page
- duplicate rate
- last page
- exhausted reason

After campaign:
update historical keyword metrics.

Next campaigns should favor historically useful keywords.

Do not permanently delete poor keywords.

==================================================
6. Search worker
==================================================

Reuse explicit search handshake architecture from Phase 2.9.1.

Requirements:
- one search worker tab per auto campaign
- persisted in chrome.storage.session
- restore after service worker restart
- DOM actual next link only
- explicit background→content capture handshake
- 6–30 sec configurable delay
- default 8 sec

No tab explosion.

==================================================
7. Detail worker
==================================================

Reuse existing one-detail-worker architecture.

Once search target reached:
SEARCH_COMPLETE → DETAILING

Queue campaign candidates.

Do not revisit:
- DETAIL_COMPLETE
- MASTER_IMPORTED
unless explicit retry is needed.

Single worker tab.
Minimum existing safe interval.

==================================================
8. Resume
==================================================

Must survive:
- UI refresh
- extension service worker restart
- ShopSource restart
- browser tab loss
- PC restart where persisted DB remains

On resume:
- same campaign ID
- reconstruct category/keyword/page position
- reconstruct search/detail worker safely
- do not repeat already captured pages
- do not duplicate MASTER

==================================================
