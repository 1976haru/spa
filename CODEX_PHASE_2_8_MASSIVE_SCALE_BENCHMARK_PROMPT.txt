==================================================
0. 목표
==================================================

사용자는 향후 실제 소싱 규모를 10,000~50,000개까지 고려하고 있다.

20/50/100개 단위 테스트는 너무 작다.
이번 Phase는 ShopSource의 내부 시스템이
10K/50K 규모를 버틸 수 있는지 빠르게 검증한다.

중요:
실제 Amazon 상품 상세 50,000개를 지금 브라우저에서 무작정 여는 것이 목표가 아니다.

현재 Browser Capture는:
- single worker tab
- 최소 4초 간격
- CAPTCHA 우회 없음

이므로 실제 50K 상세방문은 매우 오래 걸리고 차단 가능성도 커진다.

따라서 이번 Phase는 두 층으로 나눈다.

A. 시스템 대규모 성능 검증
- 1K / 10K / 50K synthetic benchmark
- 외부 network 0
- 실제 production DB 0 영향
- Spark/Shopify 업로드 0
- DB/UI/classification/package/queue 성능 확인

B. 실제 Amazon 대규모 운영 준비
- real candidate 수만 개 축적 가능 구조
- 상세 보강은 선별/우선순위 기반
- CAPTCHA 우회 없이
- 재개/checkpoint 가능한 구조

==================================================
7. 대용량 DB 쓰기 최적화
==================================================

현재 row-by-row insert가 병목인지 측정.

필요하면:

- explicit transaction
- executemany
- chunked bulk insert
- UPSERT
- WAL mode 검토
- synchronous 설정은 안전성 고려
- proper indexes

를 적용.

단 production correctness를 희생하지 않는다.

benchmark-only PRAGMA로 성능을 속이지 마라.

production-compatible 설정으로 측정.

page size:
50 / 100 / 200 / 500
허용 가능.

10. Selection 모델
==================================================

50K에서 checkbox 50K를 실제 browser DOM에 만들지 않는다.

다음 선택 방식 지원:

A. current page select
B. current filtered result select-all (logical selection)
C. explicit ASIN set
D. status-based package

filtered select-all은
50K ASIN을 browser client memory에 전부 들고 있을 필요 없게
server-side selection descriptor 사용 권장.

예:

SelectionSpec:
{
  store_id,
  filters,
  excluded_asins,
  explicit_included_asins
}

향후 10K package에서도 안정적으로 사용.

18. real Amazon scale architecture
==================================================

Benchmark와 별도로 실제 live 전략을 문서화.

50K 상세페이지를 전부 즉시 방문하는 방식은
API-free single-worker 구조에서 비효율적이다.

실제 운영은 2-stage:

STAGE 1 — Candidate harvesting
검색 결과에서:
ASIN
title
price
rating
review count
thumbnail
sponsored
keyword/page

를 빠르게 누적.

목표:
10K~50K candidate MASTER/CANDIDATE pool.

STAGE 2 — Detail enrichment
후보를 priority score로 정렬하고
실제 필요한 상품만 상세 페이지 방문.

우선순위 예:
- Store price band 근접
- title relevance
- review/rating threshold
- duplicate family 제거
- already detailed 제외
- risk/restricted keyword 제외는 삭제가 아니라 후순위/분류

즉 50K candidates 중
상위 N개만 detailed.
