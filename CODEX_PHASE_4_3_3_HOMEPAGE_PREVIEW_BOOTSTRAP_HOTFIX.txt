2) Then [추천 상품 미리보기] returned:

Confirmed root cause from current code
- src/shopsource/homepage_automation.py
- hero_image_prompt():
    avoid = profile.get("avoid_styles", "").strip()
- Current BrandProfile stores avoid_styles as a list in real Cabin Tidy data.
- This throws AttributeError before homepage design can finish.
- Because design aborts before a connected theme snapshot is stored in UI state,
  featured_preview() later calls build_theme_preview(plan, state.get("snapshot") or {})
  with an empty/unconnected snapshot, which then returns MANUAL_ACTION_REQUIRED.

This is a real type-contract/UX bug. Fix both the data normalization and the preview bootstrap.

1. TYPE-SAFE BRAND PROFILE NORMALIZATION
======================================================================

Fix homepage prompt/copy generation so BrandProfile values can safely be either:
- str
- list/tuple/set
- dict
- None

Do not call .strip() directly on an unvalidated profile value.

Add a small reusable normalization helper in homepage_automation.py, e.g.
_normalize_prompt_value(value, separator=", ")

Rules:
- None -> ""
- str -> stripped string
- list/tuple/set -> normalize non-empty members and join
- dict -> deterministic readable key/value representation or stable JSON-like text
- scalar -> str(value).strip()
- nested structures should never crash prompt generation

Use it at minimum for:
- avoid_styles
- personality / brand_keywords
- colors
- primary_category if needed
- target_country if needed

Do not mutate the stored BrandProfile.
Only normalize when rendering text/prompts.

Expected Cabin Tidy:

"Avoid: 3D, watermarks, busy patterns, thin details."

3. FEATURED PREVIEW AUTO-BOOTSTRAP
======================================================================

Current UX is fragile:
featured_preview() assumes state["snapshot"] already exists and is CONNECTED.

Upgrade src/shopsource/ui/v2.py so [추천 상품 미리보기] is self-sufficient.

When clicked:
1. Require current featured product plan (4/4 or current plan).
2. If state.snapshot is missing or status != CONNECTED:
   - run read-only ShopifyThemeReader().discover(current_store)
   - store it in state["snapshot"]
   - do NOT write theme
3. If theme snapshot is CONNECTED:
   call FeaturedProductAssignmentService().build_theme_preview(...)
4. If theme read cannot connect:
   show the exact reason/status.
5. If theme schema is genuinely unsupported after a successful read:
   show the exact capability reason separately from connection/bootstrap errors.

Do not tell the user MANUAL_ACTION_REQUIRED merely because the snapshot was never loaded.
