WHY THIS TASK EXISTS
The category-shortcut readiness engine is now store-agnostic and the full suite passes.
However Cabin Tidy previously excluded replacement/repair/fitment parts through hidden core logic.
That hidden hardcoding was correctly removed.

The remaining requirement is NOT to re-hardcode automotive logic.
Instead, ShopSource needs a reusable STORE-SPECIFIC MERCHANDISING POLICY layer that can be explicitly reviewed and approved per store.

This is important for the second real shop and future 100–200 store operation:
- core engine stays generic,
- each store can have approved merchandising exclusions,
- policies survive restarts and are not mixed into protected store JSON,
- no store-specific rules are silently inferred as final truth.

MISSION
Add a durable, versioned, approval-gated merchandising policy layer and make category shortcut readiness consume it.

Do NOT edit stores/001_cabin_tidy.json.
Do NOT hard-code Cabin Tidy, automotive, replacement, fitment, kitchen, pet, etc. in reusable core defaults.
Do NOT write Shopify.
Do NOT merge to main in this task.

1. PERSISTENT POLICY MODEL
======================================================================

Create an additive local DB model, e.g.:

store_merchandising_policies(
  policy_id TEXT PRIMARY KEY,
  store_id TEXT NOT NULL,
  purpose TEXT NOT NULL,
  version INTEGER NOT NULL,
  status TEXT NOT NULL,          -- DRAFT / APPROVED / SUPERSEDED
  policy_json TEXT NOT NULL,
  source TEXT NOT NULL,          -- MANUAL / IMPORTED_PROFILE / SUGGESTED
  created_at TEXT NOT NULL,
  approved_at TEXT,
  updated_at TEXT NOT NULL
)

Recommended purpose:
CATEGORY_SHORTCUTS

policy_json may contain:
{
  "exclude_keywords": [...],
  "exclude_phrases": [...],
  "exclude_title_patterns": [...],
  "exclude_decision_statuses": [...],
  "notes": "..."
}

Requirements:
- additive/idempotent migration
- latest APPROVED policy is active
- draft never changes eligibility
- explicit approval required
- immutable history: approving a new version supersedes prior approved version
- no credentials/secrets
- no sentinel IDs
