0. 실제 사용자 테스트 결과
==================================================

Phase 2.6.4 실제 live test는 성공했다.

실제 UI에서 확인:
- 후보 5
- 상품 상세 5/5
- MASTER 반영 5/5
- Store 분류 5/5
- 실패 0
- Batch DONE

즉:
Amazon 실제 상품 상세 → Extension handshake → DETAIL_COMPLETE → MASTER → Store classify
실전 5상품 end-to-end가 통과했다.

하지만 새 UX 문제가 확인되었다.

각 상품 처리 때마다 Amazon 새 탭이 생성되어
상품 수만큼 탭이 계속 누적된다.

향후 50개, 100개, 수백개 소싱에서는 사용할 수 없는 UX다.

이번 Phase의 목표:
"상품마다 새 탭 생성"을 없애고,
ShopSource가 소유한 Amazon 작업 탭 1개만 재사용한다.

==================================================
1. 핵심 원칙
==================================================

Concurrency는 계속 1개 유지.

기존:
item 1 → chrome.tabs.create()
item 2 → chrome.tabs.create()
item 3 → chrome.tabs.create()
...

변경:
첫 item → ShopSource Worker Tab 1개 생성
item 2 → 같은 tabId에 chrome.tabs.update(url)
item 3 → 같은 tabId에 chrome.tabs.update(url)
...
Batch 종료 → ShopSource가 만든 Worker Tab만 닫기

사용자가 직접 연 Amazon 탭은 절대 닫거나 재사용하지 않는다.

==================================================
2. ShopSource-owned worker tab
==================================================

background.js에 worker tab abstraction 추가.

예:

workerTabs:
runId -> {
  tabId,
  ownedByShopSource: true,
  createdAt
}

chrome.storage.session에도 최소 metadata 저장.

절대 저장 금지:
- cookies
- Amazon auth/session
- account info
- page content

허용:
- runId
- tabId
- createdAt

==================================================
3. openNext() 변경
==================================================

현재 openNext()는 매 item마다:

chrome.tabs.create({
  url: target.href,
  active: true
})

를 호출한다.

이를 다음으로 변경:

A. 해당 runId의 유효한 ShopSource worker tab이 없음
→ chrome.tabs.create({url, active:false})
→ worker tab으로 등록

B. worker tab이 살아 있음
→ chrome.tabs.update(tabId, {url, active:false})
→ 같은 tabId 재사용

C. 사용자가 worker tab을 직접 닫음
→ tab 조회 실패 시 metadata 제거
→ 다음 item에서 새 worker tab 1개 생성

==================================================
4. 기본은 background/inactive tab
==================================================

대량 소싱 중 사용자의 ShopSource 화면을 뺏지 않도록
worker tab 기본 생성/업데이트:

active:false

즉 사용자는 ShopSource UI에 계속 머물 수 있어야 한다.

Content script와 background handshake는
inactive tab에서도 정상 작동해야 한다.

단 CAPTCHA / Amazon confirmation이 감지되면:

chrome.tabs.update(tabId, {active:true})

로 해당 작업 탭을 사용자에게 보여준다.

사용자가 직접 확인한 뒤 재개할 수 있게 한다.

==================================================
5. 한 Batch에서 탭 최대 1개
==================================================

정상 동작 중:

100개 상품 처리
→ Amazon worker tab 생성 횟수 1
→ 같은 tabId update 99회

이어야 한다.

다음과 같은 tab explosion 금지:

100 products
→ 100 tabs

==================================================
6. Batch 종료 시 Worker Tab 정리
==================================================

Batch가 다음 상태가 되면:

DONE
CANCELLED

ShopSource가 생성한 worker tab을 닫는다.

DONE_WITH_ERRORS는 사용자가 오류를 볼 수 있으므로
즉시 닫지 않거나,
상품 처리 페이지가 필요 없으면 닫아도 되지만 정책을 명확히 한다.

권장:
DONE / CANCELLED → close
DONE_WITH_ERRORS → keep one worker tab, UI에 "작업 탭 정리" 제공
PAUSED_NEEDS_USER(CAPTCHA) → keep + active

중요:
ShopSource가 ownedByShopSource로 추적한 tab만 close.
사용자 기존 Amazon tab은 절대 close 금지.

==================================================
7. 기존 pendingTabs와 workerTabs 통합
==================================================

현재:
pendingTabs = runId → {tabId, asin, timer}

이 구조와 worker tab tracking을 충돌 없이 통합한다.

권장:

runSessions[runId] = {
  workerTabId,
  currentAsin,
  timeoutId,
  ...
}

또는 pendingTabs + workerTabs 별도 유지 가능.

중요한 invariant:

runId당 active worker tab 최대 1
runId당 DETAIL_OPENED item 최대 1

9. Fragment / handshake
==================================================

Phase 2.6.4 background-driven handshake는 그대로 유지한다.

worker tab URL에도 fragment marker를 fallback으로 붙여도 된다.

하지만 auto capture는 계속:
background → content message

가 primary.

탭 재사용이 handshake를 깨뜨리면 안 된다.

==================================================
10. 사용자 UI
==================================================

Sourcing 화면에 간단하게 표시:

"Amazon 작업 탭: 1개 사용 중"
또는
"Amazon 작업 탭: 없음"

버튼 선택 사항:

[작업 탭 보기]
[작업 탭 정리]

작업 탭 보기:
- ShopSource-owned worker tab이 있으면 active:true

작업 탭 정리:
- 현재 capture가 진행 중이면 경고 후 금지 또는 pause 요구
- 안전한 상태에서 ShopSource-owned worker tab만 close

일반 사용자는 탭 관리를 신경 쓰지 않아도 되게 한다.

==================================================
11. 기존에 이미 많이 열린 탭 정리
==================================================

Phase 2.6.4 이전에 이미 열린 Amazon 탭들을
무작정 자동으로 닫지 마라.

어떤 탭이 ShopSource 소유인지 확실한 증거가 없는 기존 탭은
사용자 탭으로 취급한다.

새 버전부터 생성된 owned worker tab만 자동 관리한다.

==================================================
13. Worker tab이 닫힌 경우
==================================================

사용자가 실수로 worker tab을 닫으면:

chrome.tabs.onRemoved에서 worker metadata 제거.

Batch DB state가 DETAIL_OPENED라면
바로 새 탭을 자동 생성하지 말고
현재 기존 recovery 정책을 사용.

사용자 explicit:
[현재 상품 다시 시도]
또는
[미완료 상품 자동 처리]

에서 새 worker tab 생성.

무한 reopen 금지.

==================================================
14. Browser/service worker restart
==================================================

chrome.storage.session에 worker metadata를 저장해
service worker suspend/restart에는 대응한다.

브라우저 완전 종료 후 session storage가 사라지는 것은 정상.

브라우저 재시작 후에는
유효하지 않은 old tabId를 신뢰하지 말고
다음 explicit kickoff에서 새 worker tab 생성.
