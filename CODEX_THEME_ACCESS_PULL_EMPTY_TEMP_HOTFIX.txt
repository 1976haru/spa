Verified Shopify CLI source behavior
Current Shopify CLI pull service validates the --path directory before download:
- if directory is empty => proceed
- if non-empty and missing required theme directories => confirmation gate
- required directories are config, layout, templates
- our current ShopSource _pull() calls _scaffold(temp) BEFORE theme pull
- _scaffold creates config + templates, but NOT layout
- therefore the temp directory becomes non-empty but is NOT recognized as a valid theme directory
- with --no-input, the CLI cannot complete the confirmation flow, so no requested file is downloaded

Current ShopSource _pull() sequence:
1. mkdtemp()
2. _scaffold(temp)  <-- creates invalid partial theme directory for pull
3. shopify theme pull ... --path temp --no-input
4. target templates/index.json missing
5. REMOTE_READ_FAILED

Mission
For read-only pull, leave the isolated temp directory EMPTY before invoking Shopify CLI.
Keep _scaffold() for push/write only.

Do NOT add hidden --force unless absolutely necessary.
Empty directory is safer and matches Shopify CLI validation behavior.
