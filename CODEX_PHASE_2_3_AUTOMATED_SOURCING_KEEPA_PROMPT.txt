==================================================
1. 외부 조사 결과를 구현 원칙으로 반영
==================================================

Amazon Creators API / PA-API를 Shopify 재판매 상품 sourcing feed로 사용하지 마라.

이유:
Amazon Associates Program의 Product Advertising Content는 Amazon으로 트래픽과 판매를 보내는 용도로 제한되어 있고,
Amazon 외 사이트의 상품 판매를 홍보하는 용도로 사용하면 안 되는 계약 구조다.

따라서 ShopSource Studio의 자동 Amazon candidate sourcing 1차 provider는:
KEEP A API (Keepa REST API)
로 구현한다.

Keepa는 Amazon product database에 대해:
- Product Finder /query
- Product Request /product
- Best Sellers /bestsellers
- Category Search / Lookup

등을 제공한다.

하지만 Keepa는 제3자 서비스다.
실제 상업적 사용 조건/라이선스는 사용자가 Keepa 약관을 확인해야 한다.
프로그램은 provider abstraction으로 만들어 특정 provider에 종속되지 않게 한다.

==================================================
2. 목표
==================================================

사용자가 매번 Amazon 검색 페이지를 열고 수동으로 상품을 찾지 않아도 되게 한다.

운영 흐름:

Store Profile
→ Sourcing Recipe
→ Keepa Product Finder
→ 후보 ASIN
→ Product Request로 상세 보강
→ prefilter/risk filter
→ canonical product JSON
→ MASTER DB
→ Store classify
→ PRIMARY/RESERVE
→ Spark Center package

이번 Phase는 "candidate sourcing 자동화"다.

Amazon 웹페이지 scraping은 하지 않는다.

3. Provider abstraction
==================================================

새 구조 권장:

src/shopsource/sourcing/
    __init__.py
    models.py
    engine.py
    recipes.py
    providers/
        __init__.py
        base.py
        keepa.py

Provider interface 예:

class SourcingProvider:
    def health(self): ...
    def estimate(self, recipe): ...
    def discover(self, recipe, checkpoint=None): ...
    def hydrate(self, asins): ...

KeepaProvider는 이 interface를 구현한다.

향후 다른 합법적 provider를 추가해도 engine/classifier/UI 변경이 최소가 되어야 한다.

4. Keepa 공식 API 사용 범위
==================================================

기본 locale:
Amazon US / domain=1

사용 endpoint:

A. Product Finder
POST https://api.keepa.com/query
- 후보 ASIN 검색
- 최대 10,000 ASIN/query
- paging/checkpoint
- token cost 추적

B. Product Request
GET https://api.keepa.com/product
- 최대 100 ASIN batch
- 기본 상세 정보 hydrate

권장 기본 params:
domain=1
stats=90
history=0

초기 대량 후보에는 offers= 사용하지 마라.
offers는 token cost가 훨씬 높다.

rating=1도 모든 후보에 무조건 적용하지 마라.
필요한 finalist에 선택적으로 사용한다.

C. Best Sellers
선택적 보조 discovery source.
기본 engine은 Product Finder를 우선한다.

GUI:
[API 설정]
→ Keepa API Key 입력
→ [연결 테스트]
→ [Windows 자격 증명에 저장]

API key는 화면에서 마스킹한다.

keyring 사용이 불가능하면:
- plaintext repo 파일 fallback 금지
- session only 또는 환경변수 사용
- 사용자에게 안내

==================================================
6. Keepa HTTP client
==================================================

requests 또는 httpx 중 프로젝트에 맞는 하나를 사용한다.

필수:
- HTTPS only
- timeout
- retry/backoff
- 429/5xx handling
- gzip 지원
- token fields parse
- no key logging
- User-Agent는 정상 앱 식별 가능하게
- max concurrency 제한

Response에서:
tokensLeft
refillIn
refillRate
tokensConsumed
processingTimeInMs

를 읽어서 run telemetry에 기록한다.

API key는 URL 전체 logging 시 반드시 redaction.

8. Cabin Tidy 1차 자동 sourcing recipe
==================================================

001 Cabin Tidy에 실제 실행 가능한 기본 recipe를 추가한다.

카테고리:
auto interior organization / convenience / storage

keyword queries는 OR을 한 request에 억지로 넣지 말고
여러 query recipe로 분리한다.

예:

- "trunk organizer"
- "car seat organizer"
- "backseat organizer"
- "center console organizer"
- "car trash can"
- "headrest hook"
- "car cup holder"
- "car gap filler"
- "car storage organizer"
- "vehicle organizer"

Store Profile의 include_keywords와 연계하되,
exclude_keywords/risk_rules도 그대로 사용한다.

가격 discovery 범위는 PRIMARY만 보지 말고 RESERVE까지 확보하기 위해:
$30 ~ $120
를 기본 candidate range로 사용한다.

즉:
PRIMARY $40~100
주변 reserve $30~40 / $100~120
까지 자동 소싱한다.

$30 미만과 $120 초과를 시스템적으로 삭제하지 말고,
이번 recipe에서 API query 범위 밖이라 discover되지 않을 뿐이라는 점을 명확히 한다.

==================================================
9. Product Finder query
==================================================

Keepa Product Finder query는 공식 필드명을 사용한다.

기본 per keyword recipe 예:

{
  "title": "trunk organizer",
  "productType": 0,
  "singleVariation": true,
  "isAdultProduct": false,
  "isHazMat": false,
  "hasReviews": true,
  "current_NEW_gte": 3000,
  "current_NEW_lte": 12000,
  "current_RATING_gte": 40,
  "current_COUNT_REVIEWS_gte": 30,
  "imageCount_gte": 2,
  "sort": [["current_SALES", "asc"]],
  "perPage": 100,
  "page": 0
}

단:
- Keepa 실제 field semantics와 unit을 공식 docs 기준으로 구현하라.
- cents ↔ dollars conversion 중앙화.
- rating Keepa 값 40 = 4.0 stars임을 코드 상수/함수로 명시.
- query filter가 너무 강해서 0건이면 자동으로 조건을 임의 완화하지 마라.
- recipe preset에서 사용자가 조정할 수 있게 한다.

월간 판매량 monthlySold는 데이터가 없는 ASIN이 많으므로 기본 hard filter로 강제하지 않는다.
ranking signal로 사용하는 것은 가능하다.

10. Candidate discovery / dedupe
==================================================

여러 recipe에서 나온 ASIN을 하나의 sourcing run 안에서 dedupe한다.

ASIN마다 provenance 보존:

- provider
- recipe_id
- keyword
- finder_page
- discovered_at
- discovery_rank
- query_hash

동일 ASIN이 여러 recipe에 걸리면:
- MASTER는 1개
- sourcing evidence는 여러 개 보존 가능

==================================================

Product Finder는 ASIN list만 반환하므로
candidate ASIN을 Product Request로 상세 보강한다.

최대 100 ASIN batch.

기본:
stats=90

Keepa Product Object에서 canonical payload로 최소 매핑:

images

_sourceUrl
_collectedAt

단, 데이터가 없는 field를 꾸며내지 마라.

==================================================
12. 가격 선택 규칙
==================================================

Keepa statistics price type indices를 공식 docs 기준 상수화한다.

최소:
AMAZON = 0
NEW = 1
SALES = 3
LISTPRICE = 4
COUNT_NEW = 11
BUY_BOX_SHIPPING = 18

기본 candidate canonical price:

1. stats.current[BUY_BOX_SHIPPING]이 유효하고 실제 데이터가 있을 때
2. stats.current[AMAZON]
3. stats.current[NEW]
4. 유효 가격이 없으면 REVIEW / source incomplete

단, BUY_BOX_SHIPPING은 buybox/offers parameter가 없으면 없을 수 있다.
대량 hydrate에서는 2→3 fallback이 주 경로가 될 수 있다.

가격은 smallest currency unit → USD float로 정확히 변환.

-1 / null은 가격 없음.

가격 없음 때문에 MASTER에서 삭제하지 않는다.
REVIEW 또는 SOURCE_INCOMPLETE로 보존.

==================================================

==================================================
24. 중요: Spark JSON compatibility
==================================================

기존 Spark handoff generator는 Spark source raw payload를 그대로 재사용하는 전략이었다.

Keepa source는 raw payload 형식이 다르다.

따라서 기존:
latest occurrence raw_json → Spark handoff

를 그대로 적용하면 안 된다.

Phase 2.3에서 source-aware export를 구현하라.

source_kind == SPARK_STORAGE:
기존 raw payload 그대로.

source_kind == KEEPA:
Keepa → Spark-compatible canonical mapping 함수 사용.

예:
to_spark_product_payload(product)

최소 Spark에서 이미 확인된 필드:
url
asin
title
brand
price
options
quantity
tags
category
overview
aboutThis
images
rating
reviewCount
_sourceUrl
_listPage
_collectedAt

Keepa에 없는 값은 안전한 empty/list/object/null로 처리하되
값을 꾸며내지 않는다.

5개 package를 Spark Desktop 또는 Spark Center에서 실제 테스트하기 전:
capability:
KEEPA_TO_SPARK_MAPPING_UNVERIFIED

유지.
