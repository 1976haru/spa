1. 현재 사용자 상황
==================================================

현재 MASTER 상품 수는 0이다.

사용자는 더 이상 C:\Users\...\AppData\Roaming\spark\storage를 기본 작업경로로 쓰고 싶어 하지 않는다.

앞으로 기본 작업영역은 프로젝트 로컬:

D:\shop\001_so_amazon

이다.

소싱 원본 기본 폴더:

<repo>/source/amazon

Spark Center 업로드 결과:

<repo>/exports/spark_center

운영 흐름:

Amazon에서 사용자가 확보한 소싱 파일
→ source/amazon
→ MASTER DB
→ Store 분류
→ PRIMARY 등 상태
→ Spark Center 업로드 package 생성
→ Spark Center 수동 업로드

이번 Phase에서는 Amazon 웹사이트를 자동 크롤링하지 않는다.

중요:
- CAPTCHA 우회 금지
- stealth/proxy rotation 금지
- Amazon session/cookie 재사용 금지
- undocumented Amazon endpoint 구현 금지

이번 Phase의 목표는 "사용자가 확보한 Amazon 상품 JSON을 프로젝트 로컬 Source Inbox에서 MASTER DB로 안전하게 가져오는 것"이다.

2. source/amazon 작업공간
==================================================

프로그램 최초 실행 또는 ensure_dirs 시 다음 폴더를 자동 생성한다.

source/
  amazon/
    inbox/
    samples_or_docs/

실제 상품 원본은:

source/amazon/inbox/

에 둔다.

단, 실제 상품 JSON은 Git에 절대 올리지 않는다.

.gitignore에 최소:

source/amazon/inbox/*
!source/amazon/inbox/.gitkeep

또는 더 안전한 동등한 규칙을 적용한다.

samples_or_docs에는 실제 Amazon 상품 payload를 넣지 마라.
문서나 synthetic 예제만 허용한다.

원본 파일은:
- 이동하지 않는다
- 삭제하지 않는다
- 이름을 바꾸지 않는다
- 덮어쓰지 않는다

읽기 전용으로 취급한다.

==================================================
3. 지원 입력 형식
==================================================

Phase 2.2에서는 확인된 JSON 계열만 지원한다.

지원해야 할 것:

A. 일반 상품 JSON 폴더
예:
source/amazon/inbox/batch_001/
  000000001.json
  000000002.json
  ...

B. 한 단계 하위 batch 폴더가 여러 개인 구조
예:
source/amazon/inbox/
  batch_001/*.json
  batch_002/*.json

C. 기존 Spark storage 폴더
storage/
  datasets/<job_id>/*.json

D. 기존 storage.zip

E. 가능하면 단일 JSON 파일

지원하지 않는 것:
- CSV
- XLSX
- HTML
- 브라우저 쿠키
- request_queue
- key_value/session pool

CSV/XLSX는 실제 필드 계약이 확인되기 전까지 추측 구현하지 않는다.

4. 일반 JSON 상품 최소 계약
==================================================

일반 JSON 상품은 최소:

asin
title

이 있어야 MASTER로 가져올 수 있다.

가능한 필드는 그대로 보존:

url
asin
title
brand
price
options
quantity
tags
category
overview
aboutThis
images
rating
reviewCount
_sourceUrl
_listPage
_collectedAt

원본 JSON object 전체를 raw_json으로 보존한다.

ShopSource 내부 필드를 원본에 삽입하지 않는다.

asin은 MASTER identity용으로 trim + uppercase 가능하지만
raw payload 자체는 변경하지 않는다.

==================================================
5. 새 Source Connector 설계
==================================================

기존 SparkStorageConnector는 Spark storage 구조 전용으로 유지한다.

새로 예를 들어:

src/shopsource/connectors/amazon_source_folder.py

또는:

src/shopsource/connectors/json_product_folder.py

를 만든다.

권장 클래스:

AmazonSourceFolderConnector

역할:
- 일반 폴더의 *.json 탐색
- batch/job 정보 추출
- payload + meta 반환
- 원본 수정 없음

meta 최소:

source_kind = "AMAZON_SOURCE_FOLDER"
batch_id
source_file
relative_path
collected_at
source_url
list_page

batch_id:
가능하면 부모 폴더명 사용.
JSON이 inbox root에 직접 있으면 안정적인 기본 batch id를 만든다.

중첩 탐색은 무제한 재귀보다 안전한 범위를 사용하거나
명확한 규칙을 문서화한다.

6. Importer 구조
==================================================

현재 import_spark()에 모든 로직을 복붙하지 마라.

MASTER upsert 공통 로직을 추출해서:

- SparkStorageConnector
- AmazonSourceFolderConnector

둘 다 같은 import core를 쓰도록 리팩터링하는 것을 권장한다.

예:

import_products(source, connector, source_type, db, allow_reimport=False)

또는 architecture에 맞는 동등한 구조.

핵심:
- ASIN unique MASTER 유지
- occurrence/history 유지
- malformed JSON 오류 기록
- raw_json 보존
- transaction/savepoint 유지
- source read-only
- 같은 원본 재가져오기 idempotent

기존 import_spark CLI/API는 깨뜨리지 마라.

==================================================
7. Import key 개선
==================================================

현재 directory import key가 디렉터리 자체 stat에만 의존하면
inbox에 새 파일이 추가될 때 안정적이지 않을 수 있다.

Phase 2.2에서 이를 점검하고 개선하라.

목표:
- 동일 batch 그대로 재import → skip 가능
- batch에 실제 파일이 추가/변경됨 → 새로운 import로 인식 가능
- 수천 파일에서 과도하게 느리지 않게

권장:
파일 상대경로 + size + mtime_ns를 정렬하여 hash

전체 파일 내용 SHA256까지 매번 읽는 것은 대량 파일에서 비쌀 수 있으므로 필요성 검토.

선택 이유를 완료 보고에 설명하라.

기존 Spark import idempotency 테스트도 유지한다.

==================================================
8. occurrence source 구분
==================================================

향후 provenance가 중요하다.

현재 product_occurrences에 필요한 경우 additive column을 검토:

source_kind
batch_id

하지만 기존 job_id를 batch id로 재사용할 수 있다면 과도한 migration은 피한다.

권장:
- Spark storage: source_kind = SPARK_STORAGE
- 프로젝트 source/amazon: source_kind = AMAZON_SOURCE_FOLDER

DB schema 변경 시 additive migration만 사용한다.

MASTER product는 출처와 관계없이 ASIN 기준 하나다.

==================================================
15. 소싱 파일 Validation
==================================================

Import 전에/중간에 다음 검증:

- JSON parse
- object 여부
- asin
- title
- 중복 ASIN 허용하되 MASTER dedupe
- payload에 credential/session cookie 키가 있으면 MASTER raw_json에 저장하지 말고 해당 파일을 REJECT 또는 import error 처리

민감 키 예:

cookie
session-token
access-token
authorization
password
secret
aws-waf-token

기존 Spark runtime session 파일은 일반 product input으로 읽지 않도록 한다.

SDK_SESSION_POOL_STATE.json
SDK_CRAWLER_STATISTICS_*.json

은 source 폴더에 실수로 있어도 상품으로 import하지 말고
skip/error reason 기록.
