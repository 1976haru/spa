Context
- Phase 4.1 passed full stress qualification.
- Phase 4.2 live-pilot prompt exists but MUST NOT be executed yet.
- User observed many "Sold out" items in the Shopify collection.
- IMPORTANT: a Shopify "Sold out" label does NOT by itself prove the Amazon source is out of stock. It can also be caused by Shopify inventory quantity/tracking/location/publication configuration.
- Current code captures price but does not provide a complete source availability history / freshness / margin guard.
- DirectShopifyProductPublisher currently uses UNMANAGED inventory by default.
- The system must distinguish:
  A. Amazon/source out of stock
  B. Shopify inventory/configuration sold-out
  C. price/margin risk
  D. unknown/stale source state

Goal
Add a source-of-truth safety layer so that:

1. new sourcing does NOT send known out-of-stock products to Spark/Shopify
2. unknown/stale availability does NOT silently become sellable
3. source price and availability are snapshotted over time
4. pre-listing requires a fresh source check
5. already listed products can be monitored for source stock/price changes
6. margin-risk decisions are store-specific
7. Amazon/source price is NEVER silently copied into Shopify selling price
8. automatic repricing is OFF by default
9. Shopify "Sold out" can be diagnosed as source-side vs Shopify-side
10. Phase 4.2 cannot write even DRAFT pilot products unless the new source freshness gate passes

ABSOLUTE SAFETY
- Do NOT run real Shopify mutations during implementation.
- Do NOT run real Keepa/API paid calls during implementation.
- Do NOT automate Amazon CAPTCHA/WAF bypass, stealth, proxies, cookies, session extraction, or undocumented auth.
- Browser Capture may only use normal page DOM already visible to the user.
- All tests use mocks/fixtures.
- Protect stores/001_cabin_tidy.json exactly as before.

7. PRICE HISTORY / DELTA
======================================================================

For every new successful source observation:
compare against the previous successful snapshot.

Track:
- previous_source_price
- current_source_price
- delta_amount
- delta_percent
- changed_at

Do not mistake currency changes for price changes.
If currency mismatch:
NEEDS_REVIEW.

Source price drop:
- update history
- selling price remains unchanged by default
- margin improves

Source price small rise:
- selling price remains unchanged by default
- evaluate margin / warning

Source price large rise:
- selling price remains unchanged by default
- block or warn according to configured margin policy

AUTO REPRICE:
OFF by default.

Never automatically lower Shopify selling price because source price fell.

Never automatically increase Shopify selling price merely because source price rose unless a future explicit bounded AUTO_REPRICE policy is enabled.

======================================================================

Configuration fields:

- still detect source price change
- do not claim margin is safe
- status NEEDS_PRICING_POLICY
- DRAFT pilot may be prepared if all other safety gates pass
- ACTIVE publication must remain blocked until user confirms a pricing guard policy

Formula:
effective_source_cost =
  current_source_price
  + configured fixed buffers
  + configured percentage buffers

estimated_margin_amount =
  selling_price - effective_source_cost

estimated_margin_percent =
  estimated_margin_amount / selling_price * 100

If both min_margin_amount and min_margin_percent are configured,
both must pass unless Store Profile explicitly defines another mode.

Do not include unknown fees/taxes/shipping as zero and then call margin "fully safe".
Report which cost components are configured vs unknown.

18. UNKNOWN / PROVIDER FAILURE POLICY
======================================================================

Provider error is not the same as OOS.

On one transient provider error:
- retain last successful snapshot
- increment consecutive_errors
- freshness moves according to age
- do not immediately mark OUT_OF_STOCK

For NEW listing:
fresh verification failure = BLOCK NEW LISTING.

For existing ACTIVE listing:
- if last successful IN_STOCK snapshot is still within configured grace/freshness window, alert/retry
- after STALE_BLOCK threshold, create PAUSE_LISTING action plan

No indefinite selling from months-old source data.
