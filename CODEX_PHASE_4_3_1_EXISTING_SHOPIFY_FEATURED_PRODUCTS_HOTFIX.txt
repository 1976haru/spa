Observed real Cabin Tidy failure
- UI path: 스토어 디자인 → 홈페이지 → 추천 상품(신상품)
- User clicked [추천 상품 자동 구성].

  상태: MANUAL_ACTION_REQUIRED
  Message:
  "실제 Shopify mapping, 판매가, 이미지, ACTIVE 상태가 검증된 상품이 필요합니다."
- UI notification said the plan was saved locally, but the assignment could not proceed.

Root cause to fix
Phase 4.3 only considers products already represented in ShopSource MASTER + store decision + shopify_product_mappings.
Cabin Tidy is a pre-existing real Shopify store built before this new feature, so it can have valid ACTIVE Shopify products that are not yet ShopSource-managed/mapped.
Featured-product merchandising must be able to safely use merchant-existing Shopify products read from Shopify without forcing ownership, rewriting product data, or fabricating MASTER records.

Important design correction
For homepage merchandising, "must exist in MASTER" was too strict for pre-existing stores.
Do NOT solve this by:
- creating fake ASINs
- creating fake MASTER products
- writing/updateing existing Shopify products
- changing DRAFT to ACTIVE
- overwriting merchant tags
- scraping Shopify admin HTML
- automating PageFly GUI
- requiring the user to manually copy four product IDs

Instead add a read-only EXISTING_SHOPIFY product source that can coexist with SHOPSOURCE_MANAGED candidates.

2. CANDIDATE UNION
======================================================================

FeaturedProductAssignmentService must support two candidate sources:

A. SHOPSOURCE_MANAGED
- current MASTER + decision + mapping path
- keep all existing safety rules

B. EXISTING_SHOPIFY
- real remote product readback
- may not have master_product_id
- must have real Shopify ID
- non-empty handle
- ACTIVE status
- valid storefront retail price from Shopify variant
- image

- remote identity verified by the read itself

Deduplicate union by:
1. shopify_product_id
2. normalized handle

If a remote product is already mapped to a ShopSource-managed product:
prefer SHOPSOURCE_MANAGED representation.

4. ONE-CLICK UI BEHAVIOR
======================================================================

The existing [추천 상품 자동 구성] button must become useful for a pre-existing store.

On click:
1. Inspect local eligible managed candidates.
2. If fewer than requested_count=4 OR if remote refresh is stale/missing:
   run read-only Shopify catalog refresh automatically.
3. Union managed + existing Shopify candidates.
4. Select four real eligible products.
5. Persist plan.
6. Render the four selected items.

No second hidden/manual setup step should be required if read_products is already granted.

UI status examples:
- "Shopify 기존 상품 23개 확인 · 추천 후보 17개 · 4개 선택 완료"

- show a button or exact existing connection/settings path to refresh authorization.
- keep existing products untouched.

If no 4 eligible remote products exist:
show counts by failure reason:

- 이미지 없음

- duplicate
