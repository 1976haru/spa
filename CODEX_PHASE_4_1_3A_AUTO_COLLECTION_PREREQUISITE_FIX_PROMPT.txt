Observed user issue:
On Homepage Automation, clicking prompt auto-generation causes:
`먼저 컬렉션 자동 설계를 완료하세요.`

Root cause confirmed in current src/shopsource/ui/v2.py:
`design()` directly queries latest store_collection_plans and raises when none exists.
This is too strict for beginner one-click UX.

Goal:
Prompt generation and Homepage Auto Complete must AUTO-RESOLVE the collection-plan prerequisite whenever safe.
The user should not have to leave the homepage screen and manually visit Collection Automation first.

==================================================
1. REQUIRED BEHAVIOR
==================================================

Add a reusable helper/service such as:
`ensure_collection_plan(store_id, *, allow_create=True)`

Behavior:
A. Existing latest valid collection plan exists
→ reuse it

B. No collection plan exists, but local prerequisites are sufficient
→ automatically create a collection plan using existing Phase 3.2 CollectionPlanner
→ NO Shopify write
→ NO image generation
→ NO external network
→ persist the newly-created local plan
→ continue prompt/homepage flow automatically

C. No collection plan exists and local prerequisites are insufficient
→ DO NOT hard-fail all prompt generation
→ generate all collection-independent prompts:
   - HERO_BANNER
   - HERO_MOBILE_CROP_GUIDE
   - HERO_ALT_TEXT
   - HEADER_SUPPORT
   - FEATURED_SUPPORT if generic-safe
   - ABOUT_BRAND
   - CONTACT_SUPPORT
   - BRAND_REUSE_GUIDANCE
→ mark collection/category prompt groups:
   `WAITING_FOR_COLLECTION_PLAN`
→ show one clear beginner action:
   [컬렉션 자동 설계 후 이어서]

Do not require Shopify remote collection mappings merely to GENERATE prompts.
Remote mappings are required only for live category shortcut apply/link verification.
