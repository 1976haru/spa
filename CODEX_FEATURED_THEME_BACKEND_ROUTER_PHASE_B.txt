B. Build/select backend BEFORE mutation.
- selection locked before write
- return backend_name + reason_code in result
- if no backend READY => MANUAL_ACTION_REQUIRED, write_performed=False

- For GraphQL adapter: existing Admin GraphQL read.
- For CLI: Theme Access CLI read.
- Parse with parse_shopify_json_document.
- Require raw hash + semantic hash to match preview source.
- require theme identity MAIN from trusted preview plus backend's verified role where backend provides role.

D. Create existing exact backup only AFTER backend pre-read passes and BEFORE write.

E. Build ThemeFileWriteRequest:
- store_id
- shop_domain
- theme_id
- filename=templates/index.json
- content=proposed_raw
- expected_remote_raw_hash=current_doc.raw_hash
- confirmed=True
- target_is_live=True
- allow_live=allow_live

F. Write only through ThemeWriteBackendRouter.write(selected,...).
- no fallback after write attempt
- capture backend status

G. Unified post-write semantic verification:
- re-read through SAME selected backend
- exact raw hash == proposed_doc.raw_hash
- parsed document == proposed
- prefix/suffix preserved
- 4 product IDs exact
- isolated diff still safe

H. Only then mark:
REMOTE_JSON_VERIFIED

Do not rely only on backend raw verification for Featured success.
Featured business verification must remain stronger.
