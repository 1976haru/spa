Why this task exists
After the category strategy feature was merged, Cabin Tidy produced:
- intended Trunk Organizers strategy match count: 84
- existing remote Shopify collection "trunk-organizers": 372 products
- reconciliation status: HIGH_CONFIDENCE_CANDIDATE

Review of the merged implementation found a concrete safety defect:
ExistingCollectionReconciliationService.propose() currently treats product-count evidence as merely:
  sane_count = isinstance(count, int) and count > 0
It does NOT compare the remote collection count/content with the intended local category membership.

Therefore a semantically over-broad remote collection can be classified HIGH_CONFIDENCE based mostly on normalized title equality, even when its membership differs drastically from the intended category.

This is a reusable multi-store safety issue and must be fixed before any existing collection adoption.

Mission
Make collection reconciliation evidence-based enough that an existing remote collection is never recommended for adoption solely because its title/handle looks right while its contents are materially wrong.

No Shopify writes.
No category strategy approval.
No collection adoption.
No main merge in this task.

======================================================================
4. CONTENT COMPATIBILITY METRICS
======================================================================

When full membership is known, compute:
- expected_count
- remote_count
- count_ratio
- intersection_count
- precision = intersection / remote
- recall = intersection / expected
- jaccard = intersection / union

Return metrics in proposal.

Suggested conservative defaults:
- VERIFIED_COMPATIBLE only when:
  recall >= 0.80
  AND precision >= 0.70
  AND count ratio is not extreme
- VERIFIED_OVERBROAD when recall is acceptable but precision < 0.70
- VERIFIED_UNDERCOVERED when precision is acceptable but recall < 0.80
- COUNT_MISMATCH when full membership unavailable but remote/expected ratio is materially large, e.g. > 1.75x or < 0.57x
- UNKNOWN when evidence insufficient

Do not hardcode domain-specific thresholds by store.
Constants may be generic and documented.

======================================================================
5. ADOPTION SAFETY GATE
======================================================================

ExistingCollectionReconciliationService.adopt() may proceed only when:
- identity is unambiguous
- content_status == VERIFIED_COMPATIBLE
- confirmed=True

If content_status is:
- VERIFIED_OVERBROAD
- VERIFIED_UNDERCOVERED
- COUNT_MISMATCH
- UNKNOWN

then normal adopt() must reject.

If a future explicit override is ever supported, it must be a separate method/flag with an additional stronger confirmation and reason; DO NOT add override in this task.

This prevents accidental linking of a wrong collection.
