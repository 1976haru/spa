2. FIX WINDOWS cp949 SUBPROCESS PATHS
======================================================================

Current ShopifyThemeCLI uses subprocess.run(... capture_output=True, text=True ...)
without an explicit encoding in multiple places.

On Korean Windows this defaults to cp949, while Shopify CLI emits UTF-8.

Harden ALL ShopifyThemeCLI subprocess paths.

A. Text/structured probes that require parsing:
- shopify version
- theme list --json with --id
- fallback theme list --json

Use:
  capture_output=True
  text=True
  encoding="utf-8"
  errors="replace"
  check=False
  explicit timeout

B. _invoke() used by pull/push:
The code does NOT need stdout/stderr contents.
Use binary capture:
  capture_output=True
  text=False
or omit text entirely.

Do not decode ignored CLI output.

Never log or return raw stdout/stderr.

Preserve:
- SHOPIFY_CLI_THEME_TOKEN env-only
- password absent argv
- canonical myshopify domain
- pull --no-input
- pull has no --json

3. STEP-5 FAILURE: DO NOT ASSUME STRICT STRING ID EQUALITY
======================================================================

Current post-write verification does:

  actual_ids = current section setting value
  product_ids_match = actual_ids == expected_ids

where expected_ids are Shopify GraphQL GIDs:
  gid://shopify/Product/<id>

This is too strict for a Shopify theme setting of type:
- product
- product_list

Shopify may persist a product reference in a theme JSON representation different from the GraphQL Admin GID used by ShopSource.
Possible safe representations to classify include:
- GraphQL product GID
- numeric product ID
- product handle

Do NOT blindly accept arbitrary values.

Use the durable selected_products.json backup, which already contains:
- shopify_product_id
- shopify_handle
for each of the exact 4 selected products.

Create a product-reference normalization/comparison layer that compares LOGICAL PRODUCT IDENTITY.

Preferred pure helpers, e.g.:

normalize_shopify_product_reference(value, selected_products)
normalize_shopify_product_reference_list(values, selected_products)
compare_shopify_product_references(actual_values, selected_products)

Rules:
- GID exact match -> map to canonical selected GID
- numeric string/integer equal to terminal numeric component of one selected GID -> map to canonical selected GID
- handle exact match to one selected shopify_handle -> map to canonical selected GID
- dict/object forms must be rejected unless explicitly proven by actual theme JSON contract and covered by tests
- unknown/ambiguous references -> mismatch
- duplicates -> mismatch
- order must remain the selected order unless actual Shopify/theme contract proves product_list order is not stable; default is order-sensitive
- exactly 4 unique logical products required

Do not call Shopify product mutations.
Do not query broad product APIs just to normalize.
