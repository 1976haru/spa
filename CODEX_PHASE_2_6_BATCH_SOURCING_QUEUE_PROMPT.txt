==================================================
0. 현재 상태와 이번 Phase 목적
==================================================

Phase 2.5 API-free browser sourcing은 구현되었고,
실제 사용자 테스트에서 Amazon 검색결과 후보 capture가 성공했다.
상품 상세 1개도 DETAIL_COMPLETE까지 실제 성공했다.

현재 문제:
- 검색결과 capture가 화면에 보이는 소수 상품 중심
- 사용자가 후보를 일일이 체크해야 함
- 상세 페이지마다 사용자가 확장 버튼을 눌러야 함
- 수백/수천 상품 운영에는 비현실적

이번 Phase의 목적:

"사용자는 검색어/목표수량을 정하고 Batch 시작만 한다.
ShopSource가 현재 수집된 후보를 자동 선별하고,
상세 보강이 필요한 후보는 안전한 소규모 batch queue로 처리하며,
완료 상품은 자동으로 MASTER/분류까지 보낸다."

단,
완전 무인 Amazon 페이지네이션 crawler를 만들지 않는다.

금지:
- CAPTCHA 우회
- WAF 우회
- stealth
- proxy rotation
- Amazon cookie/session 재사용
- undocumented endpoint
- 로그인/인증 정보 수집
- 수백 탭 동시 생성

4. 검색결과 Capture 개선
==================================================

현재 content_search.js의 viewport 제한을 제거한다.

현재 Amazon 검색 결과 DOM에 렌더된
유효한 모든:

[data-component-type="s-search-result"][data-asin]

카드를 capture한다.

주의:
- 현재 페이지 DOM만
- 자동 다음 페이지 이동 금지
- 숨겨진 비상품 카드 제외
- 빈 ASIN 제외
- 같은 ASIN 중복 제거

현재 화면 스크롤 위치와 관계없이
이미 DOM에 존재하는 검색 상품은 가져온다.

검색 결과가 lazy render라 일부만 DOM에 있으면
없는 상품을 억지로 추정하지 않는다.

==================================================
5. 검색 결과 parser 품질 개선
==================================================

실제 사용자 테스트에서 Sponsored 카드 일부는
ASIN은 잡혔지만 title이 비어 있었다.

다음 selector fallback을 강화한다.

title:
- h2 span
- h2 a span
- [data-cy="title-recipe"] span
- [data-cy="title-recipe"] h2
- a.a-link-normal.s-line-clamp-2
- aria-label/title attribute fallback

url:
- h2 a[href]
- a.a-link-normal[href*="/dp/"]
- data-cy title link

price:
- .a-price .a-offscreen
- price-whole + fraction fallback

rating/review:
aria-label fallback 강화.

Sponsored 구조도 동일 ASIN이면 후보로 보존한다.

title이 search page에서 누락돼도
ASIN/url이 유효하면 NEEDS_DETAIL로 후보 저장 가능하게 한다.
단 MASTER import에는 title 필수.

==================================================
7. Candidate 자동 선별
==================================================

검색결과 capture 이후 사용자 체크 없이 자동 판단.

순서:

1. ASIN valid
2. 현재 batch 중복 제거
3. MASTER 기존 ASIN 확인
4. Store profile exclude/risk prefilter
5. 가격이 있으면 Store sourcing price 범위 참고
6. title이 있으면 Store fit lexical check
7. completeness 판단

중요:
가격 범위 밖이라고 삭제하지 마라.

MASTER 원칙 유지:
가격은 상태 분류 기준이지 영구 삭제 기준이 아니다.

위험:
RESTRICTED/REVIEW 후보는 보존 가능.

8. Search 정보만으로 충분한 후보
==================================================

모든 후보가 반드시 상세페이지를 거칠 필요는 없다.

설정값:

search_import_min_completeness

기본값은 보수적으로 높게 설정.

단 Spark Center 실제 5상품 round-trip이 아직 검증 전이므로
초기 기본값에서는 DETAIL_COMPLETE를 MASTER 자동반영 기준으로 유지하는 것이 안전하다.

향후 실제 portal 검증 후 search-only import 기준을 낮출 수 있도록
configurable하게 설계.

9. Batch Detail Queue
==================================================

사용자 시작형 batch detail enrichment 구현.

기본:
- batch size: 20
- concurrency: 1
- 최대 concurrency: 3
- 상세 페이지 하나 성공 후 다음 항목 진행
- 실패 시 queue 계속
- CAPTCHA 감지 시 전체 batch PAUSED_NEEDS_USER

UI에서:
Batch 20 / 50 / 100 선택 가능.

1000을 입력해도 내부적으로 20개 chunk로 나눠 처리.

절대 1000개 탭을 동시에 열지 마라.

==================================================
10. 상품별 클릭 제거
==================================================

현재 상품 페이지에서 사용자가
"이 상품 ShopSource로 가져오기"를 일일이 누르는 과정을 제거한다.

방법:

ShopSource가 상세 보강용 URL을 열 때
URL fragment marker 사용:

#shopsource_capture=<batch_run_id>

fragment는 서버 request로 전송되지 않으므로
Amazon request query를 변경하지 않는다.

content_product.js는:
- 해당 marker가 있고
- extension pairing이 정상이며
- 현재 page가 product detail이면

DOM 준비 완료 후
자동으로 captureDetail()을 1회 실행한다.

자동 capture 성공:
bridge에 저장
→ 화면에 작은 성공 badge/toast
→ batch controller가 다음 item 진행

중복 자동 capture 방지:
session flag / marker processed state 사용.

==================================================
11. 자동 탭 처리
==================================================

안전한 방식으로만 구현.

우선순위:

A.
ShopSource UI가 window.open으로 1개 탭 열기
→ extension auto capture
→ bridge heartbeat/status로 완료 감지
→ 다음 탭 열기

B.
필요하면 Manifest V3 "tabs" 권한을 추가할 수 있으나
그 경우 왜 필요한지 문서화하고
Amazon/ShopSource 탭에만 사용.

기본은 A 우선.

자동 탭 닫기가 브라우저 제약 때문에 불안정하면
성공 탭을 유지해도 된다.
대신 동시에 열린 상세 탭 수를 최대 3으로 제한.

==================================================
14. Pause / Resume / Cancel
==================================================

반드시 checkpoint 가능.

PAUSE:
새 item 시작 금지.
진행 중 item은 결과 기록 후 정지.

RESUME:
DETAIL_PENDING/FAILED retry 대상부터 계속.

CANCEL:
현재 상태 보존하고 종료.
MASTER에 이미 들어간 상품은 삭제하지 않음.

앱 재시작 후에도
진행 중 batch를 조회하고 Resume 가능.

==================================================
15. Retry
==================================================

FAILED item:

기본 retry_count 최대 2.

재시도 대상:
- page load timeout
- parser incomplete
- bridge temporary error

재시도 금지:
- invalid ASIN
- explicit RESTRICTED policy error
- user SKIPPED

CAPTCHA는 FAILED가 아니라
PAUSED_NEEDS_USER.

==================================================
16. 자동 MASTER 반영
==================================================

설정:

[상세 완료 시 MASTER 자동 반영]

기본 ON으로 제안.

DETAIL_COMPLETE + 필수 asin/title 충족 시
소규모 batch transaction으로 MASTER upsert.

100개 단위 또는 20개 chunk 완료 시 commit 가능.

MASTER 반영 후:
현재 Store classify 자동 실행.

사용자가 상품마다 "MASTER로 보내기" 클릭하지 않게 한다.

기존 수동 버튼은 유지한다.
