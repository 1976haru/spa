1. REQUIRED BUG FIX — STEP 6 STOREFRONT CONFIRMATION
======================================================================

Current code in src/shopsource/ui/v2.py inside featured_storefront_check() -> save_checks():

- calls:
  confirmation = FeaturedProductAssignmentService().confirm_storefront(...)
- then incorrectly sets:
  state["featured_assignment_status"] = None
- then immediately does:
  ui.notify("추천 상품 상태: " + state["featured_assignment_status"], ...)

This can raise TypeError because None is concatenated to str.
It also throws away the actual confirmation status.

Fix the flow.

Required behavior:
- keep storefront verification state separate from final assignment step state.
- after confirm_storefront(), persist the safe returned status explicitly, e.g.
  state["featured_storefront_status"] = confirmation.get("status")
- refresh durable plan:
  state["featured_products_plan"] = FeaturedProductAssignmentService().get_plan(plan["plan_id"])
- DO NOT mark final assignment step complete here.
- state["featured_assignment_status"] must remain/reset None until step 7 confirmation.
- notify using confirmation.get("status") safely, never concatenate None.
- after successful storefront confirmation, guided resolver should advance to step 7 because refreshed plan.storefront_verified == true.

Expected success:
confirmation status should normally be STOREFRONT_VERIFIED when all four checks + remote JSON verification are valid.

User-facing message:
- success: "스토어 확인 완료. 다음은 7단계 과제 제출 확인입니다."
- otherwise: "스토어 확인 항목이 아직 남아 있습니다."
No technical status needed in beginner message.
