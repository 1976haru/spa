ShopSource Studio — Phase 3.3
SHOPIFY COLLECTION PUBLISHER + IMAGE AUTOMATION

Prerequisite:
Phase 3.2 automated collection planner complete.

Goal:
One button creates/updates Shopify collections from the ShopSource collection plan, attaches generated collection images, and publishes collections to the selected Online Store publication.

IMPORTANT:
No real Shopify write during Codex implementation/tests.
Real write happens only after explicit user click in UI.

==================================================
0. Current Shopify API direction
==================================================

Use current Shopify Admin GraphQL API.

For collection creation/update:
- use modern collection/sources/conditions model
- do NOT build new integration around deprecated ruleSet if current API supports sources
- use collectionCreate / collectionUpdate
- publish with publishablePublish
- collectionAddProducts is deprecated for new code; use modern collectionUpdate inclusion/selections if manual membership is needed

Required scopes should be checked, not guessed:
- write_products for collections
- write_publications for publishing
- file/image scope needed for file upload if using Shopify Files

If exact API schema/version differs at implementation time, inspect official Shopify docs and pin a supported API version in config.

==================================================
1. Shopify connection model
==================================================

Support multiple stores.

Never store Shopify tokens in git/plain config.

Use OS credential store/keyring or encrypted secret provider.

Store in DB only non-secret metadata:
- store_id
- shop domain
- API version
- connection status
- last verified
- publication IDs/names

UI:

==================================================
3. Idempotent sync
==================================================

Use stable mapping:
ShopSource collection_key/handle ↔ Shopify collection ID.

If already created:
update title/description/image/conditions safely.

If user manually edited Shopify collection:
detect drift.
Do not overwrite silently.
Show conflict and require explicit resolution.

Never duplicate collection on repeated sync.

==================================================
4. Automatic collection conditions
==================================================

Convert canonical local rules from Phase 3.2 into Shopify collection source conditions.

Examples:
TITLE CONTAINS "Trunk"
TAG equals "shopsource:trunk-organizers"

For future direct Shopify product upload, prefer ShopSource tags.
For existing Spark-uploaded products without controlled tags, allow title conditions.

Validate resulting collection member count after creation.

==================================================
5. Collection image provider abstraction
==================================================

Implement provider interface:

CollectionImageProvider
- generate(prompt, size/aspect, output_path)
- provider_name
- model/version
- metadata

Providers:
A. LOCAL_PLACEHOLDER / MANUAL (always available)
B. OPENAI_IMAGES (optional, only when user configures API credential)

Do not hardcode API key.
Use environment/credential store.

Default image spec:
- 1:1
- photorealistic ecommerce lifestyle
- no text/logo/watermark
- category centered
- consistent store look

Store generated images:
exports/collection_images/<store>/<collection_key>/<version>.png

Do not commit generated images.
