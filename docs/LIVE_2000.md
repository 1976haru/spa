# LIVE 과제 2,000개 운영

Phase 2.9의 LIVE preset은 Amazon의 사용자에게 보이는 검색 결과를 정상 브라우저 탐색으로 수집합니다. 사용자가 ShopSource UI에서 시작/계속을 누르기 전에는 어떤 live 탐색도 시작하지 않습니다.

## 동작과 안전 경계

- 캠페인 목표는 기본적으로 `sourced_unique_target=2000`, `detail_target=2000`입니다. ASIN이 캠페인 내 식별자이며 반복 노출은 occurrence로 보존하고 중복 수만 증가시킵니다.
- 검색은 Amazon DOM이 제공하는 next 링크만 따라가며 6–30초 간격(기본 8초)으로 ShopSource 소유 검색 탭 하나를 재사용합니다.
- 후보 목표에 도달하면 검색을 멈추고 기존 단일 상세 worker 탭에서 최소 4초 간격으로 보강합니다.
- CAPTCHA나 확인 화면은 캠페인을 `PAUSED_NEEDS_USER`로 전환합니다. CAPTCHA 우회, stealth, proxy, cookie/session 추출은 하지 않습니다.
- 모든 캠페인·키워드·후보·occurrence·이벤트·실패 상태는 SQLite에 즉시 기록되어 앱/UI/확장 재시작 후 같은 campaign ID로 계속할 수 있습니다.
- 가격 범위를 벗어난 정상 상품도 MASTER에서 삭제하지 않습니다. ShopSource 분류와 Spark의 최종 가격/재고 필터는 별개입니다.

## 실행 전과 실행 후

시작/계속 버튼은 SQLite 온라인 백업(`backups/pre_live_2000_<timestamp>.sqlite3`)을 먼저 만듭니다. 검색 탭은 확장 세션에 campaign ID별로 저장하며, 브라우저 worker 재시작 후에도 해당 탭의 완료 이벤트에 explicit content-script handshake를 보냅니다. UI는 worker 연결 상태, keyword/page, 마지막 캡처와 오류를 표시합니다. CAPTCHA/준비 timeout은 사용자 확인을 위해 일시정지 또는 오류 상태로 기록합니다. Spark Desktop staging은 기존의 새 dataset ID, 원자적 복사, SHA-256 검증 경로를 그대로 사용하며 기존 dataset을 덮어쓰지 않습니다.

상세/MASTER/Store 분류가 완료되면 캠페인 ASIN 집합으로 Spark package를 생성합니다. `RESTRICTED`와 `ARCHIVED`는 기존 package 안전 정책에 따라 staging 대상에서 제외되며 원본과 분류 사유는 DB에 남습니다.

Spark UI에서 다음 항목을 직접 확인하고 결과 기록 패널에 입력합니다.

- Spark 전체 / 포함 / 제외 수
- 이미지, ASIN/상품명, 가격 필터
- 실제 Shopify 업로드 결과와 관찰 가능한 업로드 수

Shopify 토큰은 저장하지 않습니다. `과제 summary report 생성`은 `exports/assignment_reports/<campaign_id>/`에 Markdown, JSON, keyword별 CSV 증빙을 생성하며 인증 데이터는 포함하지 않습니다.

## 실제 시작 절차

1. `chrome://extensions` 또는 `edge://extensions`에서 ShopSource Capture v0.1.6을 Reload합니다.
2. `http://127.0.0.1:8081/sourcing`을 새로고침합니다.
3. 기존 캠페인 ID `LC_aab4075226b7c41c933f`가 표시되는지 확인합니다.
4. `과제 2,000 계속`을 눌러 같은 campaign ID를 재개합니다. START를 누르거나 새 캠페인을 만들지 않습니다.
5. CAPTCHA가 나타나면 해당 탭에서 직접 해결한 다음 같은 계속 버튼을 누릅니다.
