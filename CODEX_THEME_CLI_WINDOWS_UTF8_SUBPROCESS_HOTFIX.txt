Root cause in current code
src/shopsource/shopify_theme_cli.py uses subprocess.run(... capture_output=True, text=True ...)
without explicit encoding in multiple places:
- Shopify CLI version probe
- theme list --json probe
- fallback theme list probe
- _invoke() used by theme pull/push

On Korean Windows, text=True defaults to locale encoding cp949.
Shopify CLI emits UTF-8 output and Unicode symbols (e.g. bytes beginning 0xE2).
Python reader threads attempt cp949 decoding and throw UnicodeDecodeError.

Mission
Harden EVERY ShopifyThemeCLI subprocess path against Windows locale decoding.
Do this in one compressed pass.

2. SUBPROCESS CONTRACT
======================================================================

Use TWO explicit subprocess modes.

A. STRUCTURED/TEXT PROBES that need stdout parsing:
- shopify version
- shopify theme list --json
- fallback theme list --json

These MUST use:
  capture_output=True
  text=True
  encoding="utf-8"
  errors="replace"
  check=False
  explicit timeout
  env=...

Do not rely on locale.getpreferredencoding().
Do not use cp949.
Do not globally change Windows code page.

B. PULL/PUSH _invoke() where stdout/stderr are intentionally not parsed:
Prefer BINARY capture:
  capture_output=True
  text=False
  check=False
  timeout=120
  env=...

Or omit text entirely so bytes are captured.
Do NOT decode output at all.
The code only needs returncode.
This is safer than decoding ignored CLI decoration.

Never log/return raw stdout/stderr.
