======================================================================
2. CREATE ONE CANONICAL SHOPIFY JSON DOCUMENT PARSER
======================================================================

Create a small reusable module or helper, preferably something explicit like:

src/shopsource/shopify_theme_json.py

Suggested conceptual API:

@dataclass
class ShopifyJsonDocument:
    raw: str
    parsed: dict | list
    prefix: str
    suffix: str
    raw_hash: str
    semantic_hash: str
    had_leading_comment: bool

def parse_shopify_json_document(raw: str) -> ShopifyJsonDocument
def render_shopify_json_document(document: ShopifyJsonDocument, parsed: Any) -> str

Requirements:
- accept UTF-8 BOM
- preserve exact leading whitespace/BOM
- preserve one or more leading /* ... */ block comments
- preserve whitespace between leading comments and JSON
- preserve trailing whitespace
- parse JSON content after preserved prefix
- DO NOT remove comment markers that occur inside JSON strings
- DO NOT implement a broad regex that strips /*...*/ anywhere in the document
- DO NOT accept arbitrary invalid JSON silently
- if an inline/trailing JSON comment exists outside the confirmed safe leading-prefix pattern, return a precise unsupported/invalid result rather than modifying semantics
- require parsed root type appropriate for template use when needed (dict for templates/index.json)
- return actionable error metadata on malformed/unclosed leading comment

A finite-state/prefix scanner is preferred over a broad regex.

4. RAW + SEMANTIC DRIFT MODEL
======================================================================

Current preview drift logic hashes parsed JSON only.

Upgrade safely:
- semantic hash = hash(parsed JSON)
- raw hash = hash(original raw text)

When a canonical homepage preview is created, persist enough metadata to identify the exact source body:
- before semantic hash
- before raw hash
- template filename
- theme id

At apply time:
1. re-read the exact remote raw file
2. parse with the canonical parser
3. verify theme id/role
4. compare the current raw hash against the preview's source raw hash
5. compare semantic hash as a second invariant
6. if either changed unexpectedly, return CONFLICT
7. do not write over a remote comment/header change

This is safer than silently ignoring comment-only drift.
