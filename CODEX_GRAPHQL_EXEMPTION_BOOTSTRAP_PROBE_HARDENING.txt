Independent review finding
The current GraphQL evidence model is honest, but it has a bootstrap deadlock:

- write_themes granted + no previous success => SCOPE_GRANTED_UNVERIFIED
- ADMIN_GRAPHQL capability is UNAVAILABLE unless VERIFIED_ACTIVE
- explicit ADMIN_GRAPHQL selection is therefore blocked
- GraphQL write_file() also refuses unless capability is already READY
- VERIFIED_ACTIVE is only recorded after a successful themeFilesUpsert

Therefore a newly-approved Shopify exemption can never become VERIFIED_ACTIVE through the product UI unless evidence is manually seeded.

This must be fixed before merge.

Mission
Keep AUTO conservative, but allow one explicit, user-confirmed ADMIN_GRAPHQL verification attempt when:
- read_themes granted
- write_themes granted
- exact MAIN theme identity verified
- state is SCOPE_GRANTED_UNVERIFIED
- user explicitly selected ADMIN_GRAPHQL
- existing Featured preview/business guards passed
- confirmed=True
- allow_live=True

The attempt itself is the evidence probe:
- success => VERIFIED_ACTIVE
- access denied => ACCESS_DENIED_LAST_ATTEMPT
- no automatic fallback after attempt

No live Shopify write in this implementation task; tests/mock only.

2. EXPLICIT GRAPHQL PROBE MODE
======================================================================

Add an explicit probe mode that can only be reached by selection="ADMIN_GRAPHQL".

Preferred architecture:
- FeaturedThemeBackendCoordinator.select_backend(...)
  may build/select a GraphQL adapter with allow_unverified_probe=True ONLY for explicit ADMIN_GRAPHQL selection.
- Generic ThemeWriteBackendRouter should remain conservative and reusable.

Do not make global AdminGraphQLThemeBackend behavior less safe.

For explicit ADMIN_GRAPHQL:
- if state VERIFIED_ACTIVE => normal READY
- if state SCOPE_GRANTED_UNVERIFIED and identity/scope checks pass => READY_FOR_VERIFICATION_ATTEMPT
- if state SCOPE_MISSING => blocked
- if ACCESS_DENIED_LAST_ATTEMPT => blocked by default; require a future explicit retry-reset workflow, not this task
- identity mismatch/unknown => blocked

Return reason code:
USER_SELECTED_GRAPHQL_VERIFICATION_ATTEMPT
or similarly explicit wording.

The UI must clearly display:
"GraphQL scope is granted but exemption is not yet verified. This explicit live apply will test the approved path."

Do not call it VERIFIED_ACTIVE before success.
